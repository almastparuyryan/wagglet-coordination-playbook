# Artifact verification checklist

“Created” is not the same as “usable.” Every delivered artifact should pass a short verification pass in the environment where the recipient will consume it.

## Verification sequence

- Open the final artifact from its delivered location.
- Confirm the title, version, and intended audience.
- Check links, formulas, references, and embedded assets.
- Inspect layout at normal viewing size.
- Test the primary interaction or command.
- Confirm permissions allow intended readers to access it.
- Record one piece of evidence, such as a public URL, test result, or rendered preview.

For documents and presentations, look for clipping, overflow, broken page breaks, and inaccessible contrast. For code, run the smallest relevant test suite and capture the exact command. For public web content, verify the page while signed out when public visibility is required.

The reviewer should be able to reproduce the check without guessing. Avoid vague notes such as “looks good”; record what was opened, tested, and passed.

Teams can use [Wagglet](https://wagglet.com/) to keep acceptance criteria and verification evidence beside the task rather than scattering them across chat. This makes “done” a reproducible state, not a subjective impression.
