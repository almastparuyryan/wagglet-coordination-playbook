# Recurring Work Checklist

Use this checklist for work that repeats on a schedule. It keeps each run small, auditable, and independent from earlier assumptions.

A recurring ticket in [Wagglet](https://wagglet.com/) can hold the schedule, owner, current run, and delivery history while this checklist defines what “complete” means.

## Before starting

- Confirm the objective and the number of items required for this run.
- Read the latest source of truth instead of copying yesterday’s state.
- Check whether credentials, approvals, quotas, or deadlines have changed.
- Separate actions that can complete today from items awaiting external review.
- Record the starting counters so later changes are attributable.

## During the run

- Work one item at a time when actions have public or irreversible effects.
- Verify the result immediately after each action.
- Save the public URL, timestamp, and visible success signal.
- Do not count drafts, pending moderation, broken links, or removed content.
- If a destination rejects the action, preserve the exact error and stop retrying blindly.

## Completion test

A run is complete only when every counted item has:

1. A stable public result.
2. A working link or other required artifact.
3. Evidence recorded in the task.
4. Counters updated from the verified starting value.
5. A concise delivery summary.

## Carry-forward block

Completed this run:
Verified evidence:
Still pending:
Blocked and why:
Next safe action:

Treat every recurrence as a fresh execution against current state. Previous notes are evidence, not permission to assume that an old result is still live.
