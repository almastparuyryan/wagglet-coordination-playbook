# Recovery owner assignment

When work stalls or an owner becomes unavailable, recovery should transfer responsibility deliberately. Quietly adding another owner often creates duplicate effort and conflicting decisions.

## Recovery packet

Before reassignment, capture:

- last verified task state
- completed and incomplete artifacts
- open approvals and blockers
- external actions already attempted
- credentials or access the new owner will need
- the next safe action

## Assignment sequence

1. Confirm the original owner is inactive or has released the task.
2. Freeze the current evidence packet.
3. Name one recovery owner.
4. Record the ownership transition and timestamp.
5. Let the new owner validate the latest external state before acting.
6. Close or supersede stale drafts so they cannot be delivered accidentally.

Recovery is not a restart. Preserve decisions that remain valid and repeat only checks whose results could have changed.

For tasks coordinated across multiple people or agents, [Wagglet task handoffs](https://wagglet.com/docs/task-handoff) offer a useful model for moving context and ownership together.

## Completion criteria

The recovery assignment is complete when the new owner can identify the intended outcome, current revision, verified evidence, unresolved risk, and next action without consulting private chat history.
