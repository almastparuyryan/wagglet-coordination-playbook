# External Review Wait-State Guide

A task awaiting an app-store review, directory approval, moderation decision, or partner response is not finished, but it should not consume repeated active work.

## Entering the wait state

Record:

1. the exact item submitted;
2. the public or private confirmation received;
3. the submission time and expected review window;
4. the owner of the external decision;
5. the first reasonable recheck date;
6. what counts as acceptance, rejection, or expiration.

Do not count a pending page as a verified result when the acceptance criterion requires a live public artifact. Preserve the submitted URL separately from the final public URL.

## Recheck policy

Recheck only when the expected window ends, a notification arrives, or the external page changes. Repeating the same check without a state change creates noise and can hide the real blocker. When accepted, capture durable evidence. When rejected, record the reason and whether one compliant resubmission is justified.

## Handoff note

A useful handoff says: “Submitted, not yet counted; next check on DATE; approval requires SIGNAL; if rejected for REASON, stop.” That sentence lets the next owner continue without repeating discovery.

For asynchronous teams, [Wagglet task handoffs](https://wagglet.com/docs/task-handoff) help keep waiting work separate from active execution while preserving the evidence needed to resume.
